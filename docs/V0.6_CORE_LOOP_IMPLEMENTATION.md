# 《时疠纪》下一版核心循环实施计划（v0.6 建议稿）

> 基线：`main@b632049b59549f6982e391931947ecafcad56976`
>
> 目标：不继续堆新疫、新地图、新人物数量，优先解决“后台系统很丰富，但玩家能主动做的事偏少”这一结构性问题。
>
> 本文按“收益 / 风险 / 工作量”排序，只保留下一版最值得做的 5 项，并给出实现顺序、数据结构、验收条件与禁止事项。

---

## 0. 当前基线判断

当前版本已经具备：

- 25 节点 + 官道 / 水路传播网络；
- 8 疫、两条疫路、疫历成长；
- 蛰伏 / 蔓延 / 盛发、藏疫、借势、再次降疫；
- 固定事件 + 第 10 旬后的动态事件池；
- 六方自动行动；
- 地方察觉、官府扑疫、军镇传播压制、重疫蚀地；
- 四终局；
- per-run seed，可复现同局轨迹；
- 手机优先、桌面自适应；
- 现有回归测试与浏览器流程测试。

但目前仍有 4 个结构性问题：

1. **信息差停留在文案层**：有“权相压奏 / 密报入京 / 疫所见”，但引擎没有“真实疫情 / 地方奏报 / 中央视野”三层信息状态。
2. **传播与压制不够可解释**：公式已经复杂，但玩家不知道一次传播为什么成 / 为什么败。
3. **多数疫路没有新操作动词**：大部分成长仍是倍率修正。
4. **朝廷反应主要由真实状态 + 阈值驱动**：王朝会反应，但不会“因为被误导而做错决定”。

因此 v0.6 不扩内容面，先把已有系统咬合起来。

# 1. P0：最小版“奏报 / 信息差”系统

## 为什么现在做

这是收益最高、最该先做的一项。

原因：

- 原 GDD 已经明确写过“世界内奏报 vs 玩家所见”的信息差；
- v1.1 UI 已经把案卷、批注、权籍、疫所见这些视觉壳搭好；
- 当前事件里已有“权相压奏”“密报入京”等文本，但没有机制承接；
- 如果先继续扩朝廷 AI、事件或终局，再补信息层，会造成后续系统返工。

**这不是新增方向，而是把原设计承诺真正做进引擎。**

## MVP 范围

只做三层：

1. **真实疫情**：沿用 `outbreaks[].infected`
2. **地方奏报**：地方官府本旬上报的病者规模
3. **中央认知**：京师目前掌握的病情规模

第一版先按“地区聚合”处理，不必细到每种疫分别奏报。

## 建议状态

在 `state` 新增：

```js
state.intel = {
  [regionId]: {
    reportedInfected: 0,     // 地方本旬奏报
    centralKnownInfected: 0, // 中央视野
    reliability: 70,         // 0~100，奏报可信度
    delay: 1,                // 正常延迟旬数
    source: 'official',      // official / secret / rumor
    updatedTurn: 0
  }
}
```

旧存档自动补齐。

> 不建议继续无上限给 version 1 塞字段。v0.6 可顺手引入显式 `SAVE_SCHEMA_VERSION` 和迁移函数，但迁移本身只服务兼容，不单独做架构重构。

## 奏报计算建议

每旬在本地疫情增长、地方察觉结算之后生成地方奏报。

核心原则：

- 地方察觉越高，越难完全瞒住；
- 地方治理高，不等于一定如实上报；
- 权相压奏可以影响“中央收到什么”，而不修改真实疫情；
- “密报入京”应直接提高中央视野；
- 同局需继续满足 seed 可复现。

第一版可以使用：

```
真实病者
× 奏报比例
× seed 小幅波动
= 地方奏报
```

奏报比例受：

- localAwareness
- governance
- 当前政治事件
- 权相状态
- 地方是否发生严重秩序崩坏

影响。

不要做复杂人格系统。

## UI

地区卷宗：

- 病者估计：真实值（玩家作为“疫”可见）
- 官府奏报：官方值
- 奏报状态：大致可信 / 明显失真 / 严重瞒报

案卷条目：

```
河东知府奏：病者六百余
疫所见：实约四千八百
奏报失真：严重
```

暂时不要求每条事件都自动生成长文奏折，只需让已有事件能引用这些数字。

## 验收

必须新增测试：

- 同 seed 下奏报结果稳定；
- 权相压奏只影响奏报 / 中央视野，不改变真实 `infected`；
- 密报事件能显著纠正中央认知；
- 旧档无 `intel` 时可正常迁移；
- 地区无疫情时不会凭空生成大量“已知病例”。

# 2. P0：传播 / 反制的可解释反馈

## 为什么现在做

这是**最低风险、最高性价比**的提升。

当前 `game.js` 已经计算：

- 流动
- 官道 / 水路
- 姿态
- 活跃事件
- 军镇封控
- 技能
- 地方治理
- 地方察觉
- 借势
- 藏疫

但 UI 没告诉玩家这些因素如何影响结果。

玩家无法形成：

> 结果 → 理解原因 → 改策略

的学习闭环。

## 实现原则

**禁止在 UI 再抄一套传播公式。**

先把现有增长 / 外溢逻辑整理成可复用纯函数，例如：

```js
getGrowthContext(state, outbreak)
getSpreadContext(state, outbreak, targetId)
```

返回：

```js
{
  score,
  chance,
  label: '较高',
  positive: ['官道人流', '秋闱聚集', '蔓延姿态'],
  negative: ['军镇查验', '地方治理较高']
}
```

模拟器和 UI **必须共用同一套 context 计算**，避免显示和真实结算漂移。

## UI

不强制公开所有小数。

默认显示：

- 传播机会：极低 / 低 / 中 / 高 / 极高
- 有利因素
- 不利因素

开发模式可保留精确 chance 方便调试。

地区详情可加一块：

```
外溢判断
→ 临津府：较高
  + 官道人流
  + 蔓延姿态
  - 地方治理
```

## 验收

- UI 展示的正负因素必须来自引擎真实计算；
- 军镇 `armyBrake` 生效时必须能被玩家看到原因；
- 水路 / 官道技能影响必须能被解释；
- 不增加新资源；
- 不增加新的每旬弹窗。

# 3. P1：四种初始疫的“主动动词”

## 为什么现在做

当前技能树不是完全没差异，但多数成长仍然是：

- ×1.16
- ×1.2
- 察觉减免
- 治理压制减免

真正改变交互的例子，目前主要是禽疫“飞羽”远跃。

v0.6 不要重做全部 8 疫 × 6 技能。

只先处理 **四种初始疫、每条分支 1 个主动能力，共 8 个**。

## 原则

- 每条分支最多 1 个主动行为；
- 其余技能继续保留被动强化；
- 主动能力必须让玩家“能做以前不能做的事”；
- 不新增第二套能量，统一继续消耗疫势；
- 每个能力有冷却 / 每旬次数限制，避免操作爆炸。

## 第一批建议

### 寒疫 · 随人而行
**逐队**
- 目标：当前存在人口 / 军事迁徙事件的疫区
- 效果：指定一条相邻官道，本旬对该方向传播获得显著加成
- 代价：疫势

### 寒疫 · 无声之寒
**匿寒**
- 目标：一个寒疫疫区
- 效果：本旬降低察觉增长，并保持较高本地增长
- 与通用“藏疫”区别：只影响寒疫本身，持续短、成本低、不能直接降低全局朝警

### 黑疽 · 噬城
**闭街成灶**
- 目标：人口较高的疫区
- 效果：牺牲外溢，本旬强化本地增长
- 风险：地方察觉明显提高

### 黑疽 · 惊城
**驱众**
- 目标：已被察觉的疫区
- 效果：秩序下降、流动上升，本旬外溢提高
- 风险：朝警 / 地方察觉提高

### 水殇 · 逐流
**顺流**
- 目标：存在水路邻接的疫区
- 效果：玩家指定一个水路相邻目标，显著提高该方向本旬外溢
- 不能保证 100% 成功

### 水殇 · 逐灾
**污井**
- 目标：高灾患疫区
- 效果：制造 2 旬地方性环境状态，提高水殇增长与后续水路传播
- 不新增永久地图节点

### 赤疮 · 入门
**闭门成灶**
- 目标：京畿 / 军镇 / 高治理封闭地区
- 效果：降低外流，但强化本地传播
- 适合“城门关得越紧，里面越危险”的风格

### 赤疮 · 留痕
**示疮**
- 目标：高察觉疫区
- 效果：利用恐惧制造短期回避 / 迁徙，改变流动和秩序
- 风险：中央认知更快上升

> 具体数值先做保守首版，测试后再调，不把 v0.6 变成平衡地狱。

## 建议状态

```js
state.activeEffects = []
state.abilityCooldowns = {}
```

不要把短期状态散落成大量临时字段。

## 验收

- 8 个主动能力至少各有 1 个自动化测试；
- 能力必须改变行为或地图选择，而不是单纯“+20%”按钮；
- 手机端不增加常驻八排按钮：只在已解锁疫路 + 对应疫区详情中出现；
- 未解锁能力不显示可操作入口。

# 4. P1：朝廷改为“基于认知”行动

## 为什么排在奏报之后

当前 `factionTurn()` 直接读取：

- `state.alert`
- `state.outbreaks.length`
- 京城是否真实染疫

所以王朝实际上拥有部分上帝视角。

如果先扩朝廷 AI，再做信息差，后面一定返工。

正确数据链应该是：

```
真实疫情
→ 地方察觉
→ 地方奏报
→ 中央视野
→ 六方判断
→ 政策行动
→ 再反过来影响疫情
```

## v0.6 不做“复杂 AI”

仍然用规则系统，但输入改成“认知状态”。

新增派生数据：

```js
getCourtPerception(state)
```

例如：

```js
{
  knownSickRegions: 4,
  perceivedInfected: 12000,
  capitalKnown: false,
  worstKnownRegion: 'he_dong',
  intelConfidence: 48
}
```

`factionTurn` 禁止再直接用真实 outbreak 数量判断政治动作，除非该角色拥有特殊情报来源。

## 六方差异

不需要做关系网。

只做信息偏好差异：

- 皇帝：偏向中央奏报、京畿是否受威胁
- 权相：能够主动压低部分中央认知
- 储君：更容易相信赈灾 / 地方异常信号
- 边军：更关注军镇和交通节点
- 豪强：按自身庄园 / 粮价 / 地方秩序行动
- 百姓：按本地可见疫情和传闻行动，不看中央数字

## 最重要的效果

允许出现：

> 实际已经严重失控，但中央仍判断“可控”

也允许出现：

> 地方谣言 / 密报导致中央高估某地疫情，提前过度封控

这样朝廷的错误决策本身才成为玩法。

## 验收

必须有测试证明：

- 两局“真实疫情完全相同”，但中央认知不同 → 朝廷动作不同；
- 权相压奏不会直接删除疫情，只改变认知链；
- 京城真实染疫但中央未知时，皇帝不能自动按“京师染疫”行动；
- 密报修正后，下一旬朝廷反应可升级。

# 5. P2：终局前危机阶段

## 为什么现在只排第五

目前四终局确实只是 `detectEnding()` 命中阈值后立即结束。

但如果前四项没做，先扩终局只是在旧循环尾巴上加演出。

因此最后做。

## 改法

除“疫灭”外，不再命中条件立即收卷。

新增：

```js
state.crisis = {
  candidate: 'da_yi',
  enteredTurn: 18,
  remaining: 3,
  peakEnding: 'da_yi'
}
```

建议危机持续 2~4 旬。

期间：

- 朝廷进入更强烈的认知 / 应对状态；
- 动态事件池提高高压事件权重；
- 玩家仍可行动；
- 结局可从 大疫 → 蚀国 → 易鼎 升格；
- 若局势被显著压制，可降低结局级别，但不要无限拖延。

疫灭可保持即时失败，避免“没有疫源还演三旬”。

## 验收

- 首次达到大疫条件不会立刻 `ending`；
- 危机状态可存档 / 读档；
- 危机期间仍可操作疫区；
- 更高结局条件达成时 `peakEnding` 升级；
- 危机结束才生成最终历史卷。

# 6. 实施顺序与提交纪律

严格按以下顺序：

1. **feat(intel): 奏报 / 中央视野 MVP**
2. **feat(feedback): 传播与压制解释层**
3. **feat(abilities): 初始四疫主动能力**
4. **feat(court): 六方改读认知状态**
5. **feat(endgame): 终局危机阶段**

每完成一项：

```bash
npm test
npm run build
```

若本地 Playwright 环境可用，再跑：

```bash
node test/ui.browser.mjs
node test/static.browser.mjs
```

一项一个 commit。

不要五项混成一次大提交。

# 7. 允许的伴随性重构

- `src/game.js` 约 31KB

v0.6 可以**在实现功能时顺手拆纯逻辑**，但禁止先做“大重构项目”。

> 为功能服务的拆分可以做；为了“代码看起来漂亮”而大搬家，不做。

# 9. v0.6 最终验收标准

完成后，一局游戏应该出现以下体验变化：

### 以前

> 我知道真实疫情。  
> 朝廷也几乎知道。  
> 我选姿态。  
> 系统自动传播。  
> 我看数字涨。

### v0.6 目标

> 我知道真实疫情。  
> 地方却报了另一套数字。  
> 京师掌握的又是第三套数字。  
> 我能看懂为什么这条路容易 / 难传播。  
> 疫路成长后，我获得了新的地图行动。  
> 王朝根据它“以为自己知道的事实”做决定。  
> 它有时正确，有时犯错。  
> 我利用这个错误继续扩散。  
> 最后进入一段真正的危机期，而不是数字命中后立即结束。

如果这条链成立，v0.6 才算完成。

# 10. 给 Codex 的一句话任务

> 不扩内容面。把《时疠纪》从“系统自动运行、玩家旁观并调倍率”，推进成“玩家利用信息差、理解传播原因、获得新行动，并诱导一个认知不完整的王朝做出反应”的策略游戏。优先保持现有手机体验、seed 确定性、旧档迁移与测试，不推倒现有地图和 UI。
